# 네이버 블로그 운영 (매일 3편, 자리 잡히면 2편) + 칼럼 소개 릴스

블로그 글은 사람이 붙여넣기만 하면 되도록 **사진·본문·태그를 한 페이지에** 만들어 둔다.
네이버는 블로그 글쓰기 API가 없어 자동 게시는 하지 않는다(매크로 게시는 저품질·정지 위험).

## 결과물
- `naver/<id>/post.json` 글 원본 (형식은 `naver_page.mjs` 맨 위 설명)
- `naver/<id>/NN.png` 사진 (1080×1080, `kit.mjs` 로 생성)
- `naver/<id>.html` 붙여넣기 페이지 → https://www.valuenote.co.kr/naver/<id> (noindex)
- `naver/<id>/photos.zip` 사진 묶음

id 규칙: `b` + yymmdd + 종류 글자(m 시장·매크로, w 기업 분석, f 가치투자 공부·사용법, 수시 이슈는 x). 예: b261020m, b261020w, b261020f. 처음 글 묶음은 a1~a9.

**발행량 (2026-10-19 결정)**: 매일 3편(m·w·f 한 편씩). 기본 글이 어느 정도 쌓이면 하루 2편으로 줄인다. 글자는 요일이 아니라 글 종류를 뜻한다.

## 종류별 주제 (매일 한 편씩)
- **m · 시장·매크로**: 월요일은 그날 아침(08:40) 발행된 주간 칼럼 trends/col-YYYY-MM-DD 를 블로그용으로 다시 쓴다. 화~일은 경제 레이더·금리·환율·물가·중앙은행 등 지표 하나를 골라 "과거 위기 때는 어땠고 지금은 어떤가" 식 매크로 인사이트 글을 쓴다(fx/radar, fx/rates, 이슈 로그 참고). 같은 지표는 2주 안에 다시 쓰지 않는다.
- **w · 기업 분석**: "○○ 적정 주가, 계산해 보니". 많이 검색되는 대형주와 적정 주가와 차이가 큰 회사를 번갈아 고른다. 같은 회사를 8주 안에 다시 쓰지 않는다(naver/*/post.json 제목 확인).
- **f · 가치투자 공부·사용법**: 버핏·그레이엄·멍거의 원칙, 투자자가 자주 하는 실수(PER 함정, 레버리지 ETF, 배당률 착각 등), 그리고 밸류노트 사용법 시리즈(밸류노트 소개부터 시작, 기능 하나씩)를 번갈아 쓴다. 거장의 투자 칼럼(series giants)이 새로 나왔으면 그것을 쓴다.

- **수시 · 시장 이슈** (id 끝 글자 `x`, 예: b261022x, 카테고리 '주간 시장 정리'): 정해진 요일이 아니라 '시장 이슈 감시' 예약 작업이 아래 기준에 걸릴 때만 만든다. 금리·환율·물가(CPI)·중앙은행 결정·국채·신용 위험처럼 투자자가 지금 궁금해하는 일을 밸류노트 관점(적정 주가·저평가 기업·경제 레이더에 무엇이 달라지나)으로 풀어 쓴다. 지수 등락만 전하는 속보형 글은 쓰지 않는다.
  - 기준(하나 이상): 미국 또는 한국 10년물 금리 하루 ±10bp 이상 또는 5거래일 ±20bp 이상 · 원/달러 환율 하루 ±1% 이상 또는 최근 1년 최고·최저 경신 · 코스피 또는 S&P 500 하루 ±3% 이상 · 미국 CPI·PCE·고용, 한국 CPI가 예상과 0.2%p 이상 다르게 나옴 · FOMC·한국은행·일본은행 결정이 예상과 다르거나 안내가 크게 바뀜 · 경제 레이더 종합 단계가 '경계' 이상으로 새로 올라감.
  - 하루 1편, 주 3편까지. 같은 주제는 5일 안에 다시 쓰지 않는다(단계가 한 칸 더 올라간 경우만 예외). 그날 m 글에 한 문단으로 넣고 따로 만들지 않는다.

## 글 규칙 (네이버 2026 노출 기준 반영)
근거: C-Rank(한 주제를 꾸준히 쓰는 블로그 신뢰도), D.I.A.+(글 하나의 정보 가치·독창성), AI 브리핑(질문형 소제목·요약·표·출처가 있는 글을 인용). 네이버가 공식 수치를 내지 않으므로 아래 숫자는 업계 관찰치다.
- **제목**: 콜론(:)으로 끊은 "키워드: 설명"형이 아니라, 궁금증을 주는 자연스러운 한 문장으로 쓴다. 핵심 검색어(종목·지수·인물 이름)는 앞 10자 안에, 숫자 하나를 넣는다. 질문형이면 끝에 물음표 하나. 예: "버핏은 왜 7년 전 실수를 인정하고 알파벳을 155억 달러어치 샀을까?", "코스피는 왜 일주일 만에 16%나 급락했을까, 그리고 금리는 왜 내려갔을까?", "삼성전자 적정 주가를 계산해 보니 지금 주가의 3분의 1이었습니다". 30~45자. 사실과 다른 과장·느낌표·물음표 여러 개 금지.
- **첫머리**: 표지 사진(표지 제목에도 핵심어. 네이버 썸네일로 쓰인다) → `summary` 3줄 요약(답을 먼저) → 도입 문단에서 핵심어를 한 번 더.
- **소제목**: 3~6개. 질문형("~는 왜 샀을까요?") 대신 **장면·사실을 알려 주는 문장형**으로 쓴다. 예: "1988년, 드디어 가격이 맞았습니다", "5년 동안 한 번도 적정 주가 근처에 간 적이 없습니다", "처음 산 사람은 버핏이 아니었습니다". 소제목만 이어 읽어도 이야기 줄거리가 되게 한다. 물음표 소제목은 글에 하나까지만.
- **본문 = 이야기형 (2026-10-19 결정)**: 2,000~3,500자, ~합니다체. FAQ처럼 "질문 → 답"으로 끊지 말고 한 편의 이야기로 흐르게 쓴다(참고: 메르 블로그 서술 방식).
  - **도입은 장면으로**: 결론이 아니라 날짜·장소·인물이 있는 구체적 장면이나 뒷이야기(backstory)로 연다. 예: 1987년 블랙먼데이 다음 날, 1997년 기아 부도, 2004년 구글 창업자가 버핏을 찾아간 일, 2011년 버핏의 첫 일본 방문, 2023년 삼성 반도체 15조 적자. 기업 분석 글도 숫자보다 그 회사의 사연으로 시작한다. 3줄 요약이 이미 결론을 말해 주므로 본문은 이야기부터 해도 된다.
  - **문단 사이 연결 문장**: "그런데 그때", "그 사이", "여기서 한 가지", "그로부터 N년 뒤", "그러면 지금은" 같은 다리를 놓아 끊기지 않고 읽히게 한다. 문단마다 다음 문단이 궁금해지는 한 문장으로 끝낸다.
  - **반전·대비를 하나 넣는다**: 예상과 반대로 나온 숫자(재무 점수는 실패한 투자가 더 높았다), 통념과 다른 사실(버핏이 산 것은 애플이 아니라 2016년 가격의 애플이었다). 이것이 글의 흥미를 만든다.
  - **사실만 쓴다**: 뒷이야기와 일화는 널리 알려진 확인된 사실만. 분위기를 위해 지어낸 장면·대사 금지. 숫자·날짜는 원문 그대로 유지.
  - **밸류노트 등장은 뒤쪽에서**: 이야기를 다 한 뒤 "그러면 지금 이 회사는 몇 점일까요"로 자연스럽게 넘어간다. 앞부분에서 서비스 설명을 하지 않는다.
  - 문장은 짧고 그 문장만 떼어 읽어도 뜻이 통하게. 핵심어는 본문에 3~5번 자연스럽게(억지 반복 금지).
  - 예외: **월요일 주간 시장 정리(기록형)**는 이야기형 대신 그래프·표 중심 기록형을 유지한다. 도입 한두 문단만 장면형으로 쓴다.
- **표**: 비교·숫자 정리는 `table` 블록으로 1~2개.
- **사진**: 5~7장, 모두 밸류노트가 직접 만든 것(실제 데이터 그래프 2장 이상 권장). 사진마다 핵심어가 들어간 설명(cap). 사진 속 핵심 숫자는 본문 글로도 쓴다(AI는 글을 읽는다).
- **출처**: 블로그 글에는 참고 자료 목록을 넣지 않는다(본문 문장 속에서 "~에 따르면"으로 출처를 밝힌다). 인용은 실제 출처가 있는 말만.
- **끝맺음(유입)**: 고지문 바로 앞에 ① 굵은 후킹 문장 + 1문단(글 내용과 이어지는 구체적 숫자로 궁금증, 문장은 끝까지 풀어 쓴다) ② `banner` 이미지(kit kind banner, 1080×560)에 `href` 링크. 배너 아래 텍스트 링크는 따로 달지 않는다. 링크는 밸류노트 앱 화면으로 바로 보낸다: 저평가 순위는 `https://www.valuenote.co.kr/?tab=value&mkt=KR&utm_source=naver-blog`(mkt: KR·US·JP·HK·CN·ALL), 특정 기업은 `https://www.valuenote.co.kr/?co=<코드>&q=<이름>&utm_source=naver-blog`, 그 밖에는 `https://www.valuenote.co.kr/?utm_source=naver-blog`. 홍보는 이 끝맺음에만(광고성 비중이 크면 노출이 줄어든다).
- **태그**: 12~16개. 핵심어 2~3개 + 관련 세부어(종목·지표·인물) + 넓은 주제어(주식공부·가치투자) + 밸류노트. 글과 상관없는 인기 태그 금지.
- **중복 금지**: 사이트 칼럼을 그대로 옮기지 않는다. 순서와 문장을 새로 쓴다.
- **발행 리듬**: 매일 3편(m·w·f)을 아침에 만들어 두고 사장님이 시간을 나눠 올린다. 같은 소재를 연달아 쓰지 않는다.
- 용어(claude/glossary.md): 밸류노트 점수, 재무 점수, 가격 점수, 정성 평가, 트렌드, 적정 주가, 적정 매수가(적정 주가의 70%), "적정 주가보다 N% 저평가/고평가", "적정 주가의 N배로 고평가". 쓰지 않는 말: 적정가·적정 가격·내재가치·품질 점수·저평가 점수·싸다/비싸다·무료/유료·매수 후보.
- 특정 종목 매수·매도 권유 금지. 마지막 `note`에 고지 한 줄.
- 예시: naver/a2/post.json(시장), naver/a1/post.json(거장의 투자).

## 글 틀은 종류마다 다르게 (같은 뼈대 반복 금지)
모든 글이 '표지 → 3줄 요약 → 질문 소제목 → 카드 → 배너'로 똑같으면 한 블로그 안에서 찍어 낸 글처럼 보인다. 고정하는 것은 표지·요약·고지·배너 네 가지뿐이고, 가운데는 종류별 틀을 쓴다.
- **m · 시장·매크로 = 기록형**: 그래프가 주인공. 실제 데이터 선 그래프 2~3장 + 숫자 표. 소제목은 "무엇이 / 왜 / 다음 주 확인할 것" 흐름.
- **w · 기업 분석 = 회사의 사연 → 숫자 → 시장의 걱정 → 거장의 질문**: 그 회사의 역사·전환점으로 열고(기아 1997년 부도, 삼성 2023년 적자), 점수·적정 주가를 계산한 뒤, "그러면 시장은 무엇을 걱정하는 걸까요"(반대 근거)를 거쳐, 버핏·멍거라면 어떻게 물었을지로 닫는다. 기업 카드(company·price·metrics) + 같은 업종 비교 표.
- **f · 가치투자 공부·사용법 = 이야기형**: 사건 하나를 시간순으로 따라간다. 본론 전에 뒷이야기 한 토막(버핏 여섯 살 콜라 장사, 1999년 '버핏 한물갔다' 기사). 인용(quote) 1장, 연표 표 1개. 소제목은 장면형("1988년, 드디어 가격이 맞았습니다").
- 도입 첫 문장과 끝맺음 후킹 문장은 글마다 새로 쓴다. 다른 글의 문장을 복사하지 않는다.
- 사진 구성도 섞는다. 카드만 6장이 아니라 그래프·앱 화면·카드를 섞는다.

## 문장 규칙 (카드·배너·본문 공통)
- 말하다 만 문장을 쓰지 않는다. "국내에만 16곳", "판 것보다 산 것이 많았던 분기", "금통위: 동결 여부"처럼 명사로 뚝 끊긴 꼬리말 대신 "~16곳입니다", "~더 많았습니다", "~동결하는지 확인합니다"처럼 끝까지 쓴다.
- 길어져도 풀어 쓰는 쪽을 택한다. 짧게 써야 하는 자리(버튼, 표의 칸, 숫자 이름표)는 뜻이 분명한 명사 하나로 쓴다.
- 확인하지 않은 인과·변화("~로 생겼습니다", "~로 늘었습니다")는 쓰지 않는다. 확인한 사실만 쓴다.

## 만드는 법
```
npm i --no-save --no-package-lock satori@0.10.14 @resvg/resvg-js@2.6.2 pretendard@1.3.9
node scripts/blog/kit.mjs naver/<id> /tmp/jobs.json      # 사진
python3 scripts/blog/chart.py naver/<id>/NN.png /tmp/spec.json   # 실제 데이터 선 그래프 (형식은 chart.py 맨 위)
node scripts/blog/naver_page.mjs naver/<id>              # 페이지·zip
```
그래프 데이터는 Supabase REST(anon 키, config.js)로 공개 읽기: trends/series(d: kospi·spx·트렌드), fx/rates(series.*.daily), fx/current(series.USDKRW·JPYKRW100).
월요일에는 그래프 2~4장을 blog/weekly-<yyyymmdd>/ 에 복사해 사이트 칼럼 본문에도 넣는다(예: col-2026-10-15).
사진은 열어서 확인한다(글자가 넘치거나 겹치면 문장을 줄여 다시 만든다).

## 칼럼 소개 릴스
새 칼럼(trends/col-*)이 나왔는데 `scripts/reels/specs/C<칼럼 날짜 yymmdd><g?>.json` 이 없으면 하나 만든다.
- 그날 19:30 KST 게시(`scheduled_at`), 이미 지났으면 다음 날 19:30.
- 15~25초, scripts/reels/README.md 의 대본 규칙 1~10을 그대로 지킨다. 칼럼의 핵심 숫자 하나로 시작(hook) → 2~3문장 → cta.
- 캡션 끝: "전체 칼럼은 프로필 링크 → 칼럼에서 볼 수 있습니다."
