# 네이버 블로그 운영 (매일 3편, 자리 잡히면 2편) + 칼럼 소개 릴스

블로그 글은 사람이 붙여넣기만 하면 되도록 **사진·본문·태그를 한 페이지에** 만들어 둔다.
네이버는 블로그 글쓰기 API가 없어 자동 게시는 하지 않는다(매크로 게시는 저품질·정지 위험).

## 결과물
- `naver/<id>/post.json` 글 원본 (형식은 `naver_page.mjs` 맨 위 설명)
- `naver/<id>/NN.png` 사진 (1080×1080, `kit.mjs` 로 생성)
- `naver/<id>.html` 붙여넣기 페이지 → https://www.valuenote.co.kr/naver/<id> (noindex)
- `naver/<id>/photos.zip` 사진 묶음

id 규칙: `b` + yymmdd + 종류 글자(m 시장·매크로, w 기업 분석, f 가치투자 공부·사용법, 수시 이슈는 x). 예: b261020m, b261020w, b261020f. 처음 글 묶음은 a1~a9.

**발행량 (2026-10-19 결정)**: 매일 3편(m·w·f 한 편씩). 기본 글이 어느 정도 쌓이면 하루 2편으로 줄인다. 글자는 요일이 아니라 글 종류를 뜻한다.

## 종류별 주제 (매일 한 편씩)
- **m · 시장·매크로**: 월요일은 그날 아침(08:40) 발행된 주간 칼럼 trends/col-YYYY-MM-DD 를 블로그용으로 다시 쓴다. 화~일은 경제 레이더·금리·환율·물가·중앙은행 등 지표 하나를 골라 "과거 위기 때는 어땠고 지금은 어떤가" 식 매크로 인사이트 글을 쓴다(fx/radar, fx/rates, 이슈 로그 참고). 같은 지표는 2주 안에 다시 쓰지 않는다.
- **w · 기업 분석**: "○○ 적정 주가, 계산해 보니". 많이 검색되는 대형주와 적정 주가와 차이가 큰 회사를 번갈아 고른다. 같은 회사를 8주 안에 다시 쓰지 않는다(naver/*/post.json 제목 확인).
- **f · 가치투자 공부·사용법**: 버핏·그레이엄·멍거의 원칙, 투자자가 자주 하는 실수(PER 함정, 레버리지 ETF, 배당률 착각 등), 그리고 밸류노트 사용법 시리즈(밸류노트 소개부터 시작, 기능 하나씩)를 번갈아 쓴다. 거장의 투자 칼럼(series giants)이 새로 나왔으면 그것을 쓴다.

- **수시 · 시장 이슈** (id 끝 글자 `x`, 예: b261022x, 카테고리 '주간 시장 정리'): 정해진 요일이 아니라 '시장 이슈 감시' 예약 작업이 아래 기준에 걸릴 때만 만든다. 금리·환율·물가(CPI)·중앙은행 결정·국채·신용 위험처럼 투자자가 지금 궁금해하는 일을 밸류노트 관점(적정 주가·저평가 기업·경제 레이더에 무엇이 달라지나)으로 풀어 쓴다. 지수 등락만 전하는 속보형 글은 쓰지 않는다.
  - 기준(하나 이상): 미국 또는 한국 10년물 금리 하루 ±10bp 이상 또는 5거래일 ±20bp 이상 · 원/달러 환율 하루 ±1% 이상 또는 최근 1년 최고·최저 경신 · 코스피 또는 S&P 500 하루 ±3% 이상 · 미국 CPI·PCE·고용, 한국 CPI가 예상과 0.2%p 이상 다르게 나옴 · FOMC·한국은행·일본은행 결정이 예상과 다르거나 안내가 크게 바뀜 · 경제 레이더 종합 단계가 '경계' 이상으로 새로 올라감.
  - 하루 1편, 주 3편까지. 같은 주제는 5일 안에 다시 쓰지 않는다(단계가 한 칸 더 올라간 경우만 예외). 그날 m 글에 한 문단으로 넣고 따로 만들지 않는다.

## AI 양산 글로 걸러지지 않게 (2026-10-19 결정)
네이버는 'AI가 썼는지'를 잡아내서 거르지 않는다. 걸리는 이유는 AI 글에 흔한 세 가지, **원본성이 없고(다른 글과 비슷), 구조가 매번 같고, 사실이 틀리는 것**이다. 브라우저로 한 글자씩 쳐 넣는 매크로나 문체만 다듬는 도구로는 이 셋이 해결되지 않는다(오히려 매크로는 어뷰징 신호). 그래서 글 안에 밸류노트만 가진 데이터를 넣고, 사실을 확인하고, 뼈대를 바꾼다.
1. **원본 데이터가 글의 중심**: 사진 가운데 밸류노트만 가진 것(실제 데이터 그래프 `chart`, 실제 앱 화면 `app`, 점수·적정 주가 계산 카드 `data`)이 2장 이상, 그중 그래프나 앱 화면이 1장 이상. 사진 블록마다 `"kind"`를 단다(cover·chart·app·data·card·banner). 사진 속 숫자는 본문 문장으로도 쓴다. 인터넷 어디에나 있는 이야기(버핏 일화 등)만으로 글을 채우지 않는다.
2. **정답 먼저(AI 브리핑 인용용)**: 이야기형은 유지하되, 소제목 바로 아래 첫 문장은 그 단락의 답을 사실·숫자로 말한다(예: "시장이 걱정하는 것은 크게 네 가지입니다.", "기아의 주당순이익은 최근 5년 동안 연평균 13% 늘었습니다."). 소제목 아래를 사진·표로 시작하지 않는다. 뒷이야기는 그다음 문장부터.
3. **사실 표(facts)**: post.json 에 `"facts": [{"t": "확인한 사실과 숫자", "src": "출처 URL 또는 VN"}]`를 단다. 제목·요약·소제목의 숫자는 전부 여기 있어야 하고, 본문 숫자도 가능한 한 넣는다. 바깥 사실(역사·뉴스·인용·증권사 숫자)은 이번에 웹에서 확인한 URL만. 확인이 안 되면 문장을 빼거나 "~로 알려져 있습니다"가 아니라 확인되는 범위로 고쳐 쓴다(예: "부도" → "부도유예협약 대상", "역사상 최대" → "가장 큰 성과 가운데 하나"). `VN` 은 밸류노트 데이터.
4. **뼈대 바꾸기**: 최근 글과 블록 순서가 거의 같으면 안 된다. 표를 앞에 두는 글, 그래프로 여는 글, 소제목 3개짜리·6개짜리를 섞는다.
5. **문장 재사용 금지**: 다른 글과 같은 문장(20자 이상)은 쓰지 않는다. AI 상투어("결론적으로", "~라고 할 수 있습니다", "매우 중요합니다", "살펴보았습니다" 등)를 쓰지 않는다.
6. **올리는 리듬**: 같은 날 글은 3시간 이상 띄우고, 올리는 시각을 매일 조금씩 바꾼다. 매크로·예약 자동 게시는 쓰지 않는다(사람이 붙여넣기).
7. **출고 전 점검**: `node scripts/blog/check_post.mjs naver/<id>` 가 오류 없이 끝나야 한다. 경고는 읽고 고칠 수 있으면 고친다(뼈대·리드 길이·본문 숫자 출처).

## 점수·적정 주가는 시점을 맞춘다 (2026-10-21 운영자 지시)
지금(기준일) 계산한 점수·적정 주가로 과거의 매수 결정이나 과거 주가를 평가하지 않는다. 2026년 점수를 들이밀며 "6년 전 워렌 버핏은 점수 밖의 것을 봤다"고 쓰면 틀린다. 그사이 주가가 4~7배 오르면 가격 점수는 당연히 내려간다.
- **과거 매수 이야기**: 그때의 숫자로 설명한다. 공식과 상관없는 사실(매수 당시 PER·PBR·배당수익률·주가)을 "매수 당시 ○배 → 지금 ○배"처럼 두 시점으로 나란히 쓴다(예: naver/a9 일본 상사). 지금 점수는 "지금"이라고 밝혀 함께 쓸 수 있지만, 지금 점수로 과거 판단을 평가하지 않는다.
- **매수 당시 점수는 쓰지 않는다(재검증 전까지)**: index.html `VALIDATION.purchases`의 버크셔 62건 점수(b·q·v)는 2026-10-19 적정 주가 공식 개편 전 값이다(claude/valuation-method.md "콘텐츠 주의"). 새 공식으로 재검증하기 전에는 새 콘텐츠에 "매수 당시 ○○점"을 쓰지 않는다. 같은 자료의 `per`(매수 당시 PER)는 공식과 무관한 사실이라 써도 된다.
- **주가 그래프의 적정 주가 선**: 적정 주가는 지금의 이익으로 계산한 값이다. 과거 주가 위에 가로선으로 겹치면 그래프 제목에 "지금 계산한 적정 주가"를 쓰고, 본문에서 "○년 동안 저평가였다/적정 주가 아래였다"고 결론 내리지 않는다(과거에는 이익이 달라 적정 주가도 달랐다). 쓸 때는 "지금 기준선으로 재면"처럼 시점을 밝힌다.
- 이 규칙은 블로그·칼럼·릴스·DM 정리본·랜딩 페이지·관리자 문구까지 밸류노트가 내보내는 모든 글에 적용한다. check_post.mjs 가 의심 문장을 "시점 확인" 경고로 알려 주며, 이 경고는 0개가 될 때까지 고친다(고칠 수 없는 오탐이면 이유를 최종 메시지에 적는다).
- 숫자마다 "언제 기준인가"를 스스로 묻는다: 점수·적정 주가·PER·PBR·배당률·순위는 모두 기준일이 있다. 과거 사건 문단에 지금 숫자가 들어가면 기준일을 문장 안에 쓴다.

## 사진·GIF는 실사 위주 (2026-10-19 결정)
카드뉴스형 디자인 이미지가 많을수록 AI가 찍어 낸 글처럼 보인다. 그래서 블로그 사진은 사람이 찍은 듯한 **무료 실사 사진·GIF**를 중심에 두고, 디자인 이미지는 밸류노트만 가진 데이터를 보여 줄 때만 쓴다.
- **소재 창고**: `scripts/blog/media/lib/` (사진 1280×720 JPG, 영상 8초 1280×720 소리 없음 MP4). 목록·출처는 `lib/index.json`(파일 → 제목·원본 주소·라이선스·id). 출처는 Mixkit Free License(상업적 이용 가능, 출처 표기 불필요). GitHub Secrets 에 `PEXELS_API_KEY` 를 넣으면 Pexels 사진도 함께 받는다.
- **소재가 더 필요하면**: `scripts/blog/media/wants.json` 의 `ids`(글에 맞는 장면을 Mixkit에서 골라 번호·제목 적기, 사진 2장+영상) 또는 `tags`(Mixkit 태그 앞쪽 N개, 사진만)에 추가해 push 하면 blog-media 작업이 받아서 커밋한다(작업 공간에서는 Mixkit에 직접 접속할 수 없다). 장면은 WebFetch 로 https://mixkit.co/free-stock-video/<태그>/ 를 열어 제목과 번호를 보고 고른다.
- **한 글의 구성 (사진 5~7장 + 움직이는 사진(GIF) 1개)**:
  - 표지 1장 = **실사 사진 표지**(kit `photocover`, 사진 위에 제목). 표지 블록에 사진의 `src` 를 단다.
  - 실사 사진 2~3장(`kind: "photo"`, kit `photo` 로 lib 사진을 복사) — 장면이 바뀌는 문단 바로 뒤에.
  - 움직이는 사진(GIF) 1개 권장 (2026-10-19 결정: 영상 대신 GIF). `bash scripts/blog/to_gif.sh scripts/blog/media/lib/<장면>.mp4 naver/<id>/g1.gif [시작 초]` 로 만들고(가로 640px·초당 10장·4초·6MB 이하) `{"img": "g1.gif", "kind": "gif", "src": "mixkit:<번호>", "alt": "..."}` 로 단다. 사진처럼 본문 복사에 함께 들어가므로 사장님이 영상을 따로 받아 올릴 필요가 없다. `{"video": ...}` 블록은 쓰지 않는다(점검에서 오류). GIF는 사진 장수(5~7장)에 세지 않는다.
  - 밸류노트만 가진 이미지 2~3장: 실제 데이터 그래프(chart)·앱 화면(app) 1장 이상 + 점수·적정 주가 카드(data) 2장까지.
  - 글자 카드(card: 요점 목록·인용·숫자 모음)는 **1장까지**. 그 내용은 본문 문장과 표로 쓴다.
  - 끝맺음 배너 1장(그대로).
- **사진 설명(cap)은 최소로 (2026-10-19 결정)**: 사진 밑에 붙는 설명 문장("경제면 신문을 펼쳐 든 손. 13F가 나오면…")은 AI가 쓴 티가 난다. 실사 사진·GIF·표지에는 설명을 달지 않고, 보이지 않는 대체 글 `alt`(예: "신문을 읽는 손")만 단다. 데이터 이미지(chart·app·data·card)는 30자 이내 명사로만 끝낸다(예: "기아 최근 5년 월말 주가", "밸류노트 기업 지도"). 문장·콜론·마침표 금지. 무료 소재는 그 회사·장소·사람이 아니므로 alt 에도 회사·인물 이름을 쓰지 않는다. 실존 인물 사진(버핏 등)·회사 로고·제품 사진은 쓰지 않는다.
- 같은 사진을 최근 2주 안의 다른 글에 다시 쓰지 않는다(`naver/*/post.json` 의 src 확인).
- 점검(check_post.mjs)이 표지 실사·실사 사진 2장·카드 1장 이하·출처·회사 이름 설명을 확인한다.

## 글 규칙 (네이버 2026 노출 기준 반영)
근거: C-Rank(한 주제를 꾸준히 쓰는 블로그 신뢰도), D.I.A.+(글 하나의 정보 가치·독창성), AI 브리핑(질문형 소제목·요약·표·출처가 있는 글을 인용). 네이버가 공식 수치를 내지 않으므로 아래 숫자는 업계 관찰치다.
- **제목**: 콜론(:)으로 끊은 "키워드: 설명"형이 아니라, 궁금증을 주는 자연스러운 한 문장으로 쓴다. 핵심 검색어(종목·지수·인물 이름)는 앞 10자 안에, 숫자 하나를 넣는다. 질문형이면 끝에 물음표 하나. 예: "버핏은 왜 7년 전 실수를 인정하고 알파벳을 155억 달러어치 샀을까?", "코스피는 왜 일주일 만에 16%나 급락했을까, 그리고 금리는 왜 내려갔을까?", "삼성전자 적정 주가를 계산해 보니 지금 주가의 3분의 1이었습니다". 30~45자. 사실과 다른 과장·느낌표·물음표 여러 개 금지.
- **제목은 처음 보는 사람 기준 (2026-10-20 운영자 지시)**: 밸류노트 안에서만 통하는 말("34% 저평가", "워렌 버핏의 질문", "정성 평가 탈락", "장단기 금리차 0.88%p")을 제목에 쓰지 않는다. 저평가 회사는 "상승 여력 N%"(적정 주가 ÷ 현재가 − 1), 고평가 회사는 "적정 주가는 지금의 4분의 1"처럼 분수로, 기준은 "워렌 버핏이라면 어떻게 평가할까"처럼 누구나 아는 말로 쓴다. 워렌 버핏이 실제로 평가하지 않은 회사에 "워렌 버핏은 ○○를 어떻게 평가했을까"라고 쓰지 않는다(사실과 다름). "버크셔"만 쓰지 말고 "워렌 버핏의 버크셔", "알파벳"은 "구글"처럼 대중이 아는 이름으로. 예: "크래프톤 주가, 52% 상승 여력이 있다는데 워렌 버핏이라면 어떻게 평가할까?", "삼성전자는 한 분기에 100조 원을 벌었는데 왜 고평가라고 할까?"

- **첫머리**: 표지 사진(표지 제목에도 핵심어. 네이버 썸네일로 쓰인다) → `summary` 3줄 요약(답을 먼저) → 도입 문단에서 핵심어를 한 번 더.
- **소제목**: 3~6개. 질문형("~는 왜 샀을까요?") 대신 **장면·사실을 알려 주는 문장형**으로 쓴다. 예: "1988년, 드디어 가격이 맞았습니다", "5년 전에는 이익도 적정 주가도 더 작았습니다", "처음 산 사람은 버핏이 아니었습니다". 소제목만 이어 읽어도 이야기 줄거리가 되게 한다. 물음표 소제목은 글에 하나까지만.
- **본문 = 이야기형 (2026-10-19 결정)**: 2,000~3,500자, ~합니다체. FAQ처럼 "질문 → 답"으로 끊지 말고 한 편의 이야기로 흐르게 쓴다(참고: 메르 블로그 서술 방식).
  - **도입은 장면으로**: 결론이 아니라 날짜·장소·인물이 있는 구체적 장면이나 뒷이야기(backstory)로 연다. 예: 1987년 블랙먼데이 다음 날, 1997년 기아 부도, 2004년 구글 창업자가 버핏을 찾아간 일, 2011년 버핏의 첫 일본 방문, 2023년 삼성 반도체 15조 적자. 기업 분석 글도 숫자보다 그 회사의 사연으로 시작한다. 3줄 요약이 이미 결론을 말해 주므로 본문은 이야기부터 해도 된다.
  - **문단 사이 연결 문장**: "그런데 그때", "그 사이", "여기서 한 가지", "그로부터 N년 뒤", "그러면 지금은" 같은 다리를 놓아 끊기지 않고 읽히게 한다. 문단마다 다음 문단이 궁금해지는 한 문장으로 끝낸다.
  - **반전·대비를 하나 넣는다**: 예상과 반대로 나온 숫자(재무 점수는 실패한 투자가 더 높았다), 통념과 다른 사실(버핏이 산 것은 애플이 아니라 2016년 가격의 애플이었다). 이것이 글의 흥미를 만든다.
  - **사실만 쓴다**: 뒷이야기와 일화는 널리 알려진 확인된 사실만. 분위기를 위해 지어낸 장면·대사 금지. 숫자·날짜는 원문 그대로 유지.
  - **밸류노트 등장은 뒤쪽에서**: 이야기를 다 한 뒤 "그러면 지금 이 회사는 몇 점일까요"로 자연스럽게 넘어간다. 앞부분에서 서비스 설명을 하지 않는다.
  - 문장은 짧고 그 문장만 떼어 읽어도 뜻이 통하게. 핵심어는 본문에 3~5번 자연스럽게(억지 반복 금지).
  - 예외: **월요일 주간 시장 정리(기록형)**는 이야기형 대신 그래프·표 중심 기록형을 유지한다. 도입 한두 문단만 장면형으로 쓴다.
- **에디터 필명·인사 (2026-10-19 결정)**: 모든 글(블로그·사이트 칼럼)은 필명 **Editor: Luciano**(운영자의 필명)로 쓴다. 기자·칼럼니스트가 쓴 글처럼, 살짝 캐주얼하게.
  - 3줄 요약 바로 다음 첫 문단 = 인사 + 오늘 이야기 예고(2~3문장). 예: "안녕하세요, 밸류노트 에디터 Luciano입니다. 오늘은 숫자만 보면 너무 낮아서 오히려 의심이 드는 회사, 기아를 들여다보겠습니다." m 글(시장)은 "한 주 잘 보내셨나요"·"월요일 아침입니다"처럼 그날에 맞게. 인사 문장은 글마다 다르게 쓴다(같은 날 세 편이 같은 인사로 시작하지 않게).
  - 굵은 후킹 문단 바로 앞 = 맺음말 1~2문장(독자에게 건네는 말, 다음 글 예고 등) + `{"p": "— Editor: Luciano"}` 한 줄(붙여넣기 페이지에서 오른쪽 정렬·굵게 표시됨).
  - `note` 고지 끝에 "밸류노트 데이터와 AI 도구로 초안을 만들고 에디터 Luciano가 검수했습니다."를 붙인다.
  - 필명의 한계: 지어낸 개인 경험·매매·보유 종목·장소·감정은 쓰지 않는다("제가 어제 마트에서", "저도 샀습니다" 금지). "~라고 생각합니다", "이번 주 떠오른 문장은" 같은 편집자 의견 표현은 괜찮다.

- **표**: 비교·숫자 정리는 `table` 블록으로 1~2개.

- **출처**: 블로그 글에는 참고 자료 목록을 넣지 않는다(본문 문장 속에서 "~에 따르면"으로 출처를 밝힌다). 인용은 실제 출처가 있는 말만.

  3. **개념어 1~3개**: 글이 실제로 설명한 개념만(PER, PBR, 안전마진, 경제적해자, 서킷브레이커).

  - **인물 이름 (2026-10-20 운영자 지시)**: 모든 글·사진·태그에서 버핏은 **워렌 버핏**, 멍거는 **찰리 멍거**로 쓴다("버핏"만 쓰면 모르는 사람이 있다). 태그는 `워렌버핏`·`찰리멍거`. 표준 표기 `워런버핏`은 검색용으로 태그에만 하나 더 넣을 수 있다.

## 적정 주가·점수 숫자 (2026-10-19 공식 개편 뒤 반드시)
적정 주가 계산이 2026-10-19 바뀌었다(전체 기준: 프로젝트 문서 claude/valuation-method.md, 코드 index.html `scoreRow`). 글에 쓰는 회사 숫자는 아래를 지킨다.
- **숫자는 그날 데이터에서만**: 밸류노트 점수·재무 점수·가격 점수는 c/scores.json, 적정 주가는 기업 페이지(c/<slug>.html 제목) 또는 kit.mjs 의 company·price 카드에서 가져온다. 예전 글·카드뉴스·릴스·프로젝트 문서(claude/blog/naver-posts-5-7.md 등)의 숫자를 옮기지 않는다. check_post.mjs 가 글 속 회사 점수(3점 이상 차이)·적정 주가(3% 이상 차이)를 지금 계산과 대조해 오류로 잡는다.
- **계산 방식 설명은 그 회사에 실제로 쓰인 방식으로**: 기업 페이지·앱 심사 화면의 "적정 주가 기준"을 확인하고 그대로 쓴다.
  - 경기순환 보정(자동차·철강·화학·해운·조선·건설·증권, 이익 정점): 평균·최근 이익 중 작은 값, 성장 없음, 그 이익의 최대 10배. 기아 181,784원이 예.
  - 꾸준한 우량주(적자 없음, 최저 ROE 12%+·국내 10%+, 매출·이익 꾸준히 성장): 최근 이익 기준, 과거 성장의 75%(최대 12%). 마이크로소프트·알파벳·코카콜라가 예.
  - 금융사: 주당순자산 × (ROE − 영구성장) ÷ (할인율 − 영구성장). 지주회사: 30% 할인.
  - "과거 평균 이익으로 계산해서 성장주는 고평가로 나온다" 같은 개편 전 설명은 쓰지 않는다.
- **표기**: 2배 미만은 "적정 주가보다 63% 고평가", 2배 이상은 "적정 주가의 3.1배로 고평가". 같은 글 안에서 한 가지로.
- **버크셔 62건 검증 수치(60점 이상 실패율 15%, 60점 미만 37%)는 쓰지 않는다**: 10/12 공식 기준이라 새 공식으로 재검증하기 전까지 금지(check_post.mjs 오류). 검증 이야기를 꼭 해야 하면 "새 기준으로 다시 검증하는 중"이라고 쓴다.
- 점수가 크게 바뀐 회사(정성 평가가 새로 들어간 날 등)를 쓸 때는 "N월 N일 종가 기준"을 문장에 밝힌다.

## 글 틀은 종류마다 다르게 (같은 뼈대 반복 금지)
모든 글이 '표지 → 3줄 요약 → 질문 소제목 → 카드 → 배너'로 똑같으면 한 블로그 안에서 찍어 낸 글처럼 보인다. 고정하는 것은 표지·요약·고지·배너 네 가지뿐이고, 가운데는 종류별 틀을 쓴다.
- **m · 시장·매크로 = 기록형**: 그래프가 주인공. 실제 데이터 선 그래프 2~3장 + 숫자 표. 소제목은 "무엇이 / 왜 / 다음 주 확인할 것" 흐름.
- **w · 기업 분석 = 회사의 사연 → 숫자 → 시장의 걱정 → 거장의 질문**: 그 회사의 역사·전환점으로 열고(기아 1997년 부도, 삼성 2023년 적자), 점수·적정 주가를 계산한 뒤, "그러면 시장은 무엇을 걱정하는 걸까요"(반대 근거)를 거쳐, 버핏·멍거라면 어떻게 물었을지로 닫는다. 기업 카드(company·price·metrics) + 같은 업종 비교 표.
- **f · 가치투자 공부·사용법 = 이야기형**: 사건 하나를 시간순으로 따라간다. 본론 전에 뒷이야기 한 토막(버핏 여섯 살 콜라 장사, 1999년 '버핏 한물갔다' 기사). 인용(quote) 1장, 연표 표 1개. 소제목은 장면형("1988년, 드디어 가격이 맞았습니다").
- 도입 첫 문장과 끝맺음 후킹 문장은 글마다 새로 쓴다. 다른 글의 문장을 복사하지 않는다.
- 사진 구성도 섞는다. 실사 사진·GIF를 중심에 두고 그래프·앱 화면을 섞는다. 글자 카드는 1장까지.

## 문장 규칙 (카드·배너·본문 공통)
- 말하다 만 문장을 쓰지 않는다. "국내에만 16곳", "판 것보다 산 것이 많았던 분기", "금통위: 동결 여부"처럼 명사로 뚝 끊긴 꼬리말 대신 "~16곳입니다", "~더 많았습니다", "~동결하는지 확인합니다"처럼 끝까지 쓴다.
- 길어져도 풀어 쓰는 쪽을 택한다. 짧게 써야 하는 자리(버튼, 표의 칸, 숫자 이름표)는 뜻이 분명한 명사 하나로 쓴다.
- 확인하지 않은 인과·변화("~로 생겼습니다", "~로 늘었습니다")는 쓰지 않는다. 확인한 사실만 쓴다.

## 만드는 법
```
npm i --no-save --no-package-lock satori@0.10.14 @resvg/resvg-js@2.6.2 pretendard@1.3.9
node scripts/blog/kit.mjs naver/<id> /tmp/jobs.json      # 표지(photocover)·실사 사진(photo)·데이터 카드·배너
python3 scripts/blog/chart.py naver/<id>/NN.png /tmp/spec.json   # 실제 데이터 선 그래프 (형식은 chart.py 맨 위)
node scripts/blog/check_post.mjs naver/<id>              # 출고 전 점검 (오류 0개여야 함)
node scripts/blog/naver_page.mjs naver/<id>              # 페이지·zip
```
그래프 데이터는 Supabase REST(anon 키, config.js)로 공개 읽기: trends/series(d: kospi·spx·트렌드), fx/rates(series.*.daily), fx/current(series.USDKRW·JPYKRW100).
월요일에는 그래프 2~4장을 blog/weekly-<yyyymmdd>/ 에 복사해 사이트 칼럼 본문에도 넣는다(예: col-2026-10-15).
사진은 열어서 확인한다(글자가 넘치거나 겹치면 문장을 줄여 다시 만든다).

## 칼럼 소개 릴스
새 칼럼(trends/col-*)이 나왔는데 `scripts/reels/specs/C<칼럼 날짜 yymmdd><g?>.json` 이 없으면 하나 만든다.
- 그날 19:30 KST 게시(`scheduled_at`), 이미 지났으면 다음 날 19:30.
- 15~25초, scripts/reels/README.md 의 대본 규칙 1~10을 그대로 지킨다. 칼럼의 핵심 숫자 하나로 시작(hook) → 2~3문장 → cta.
- 캡션 끝: "전체 칼럼은 프로필 링크 → 칼럼에서 볼 수 있습니다."
