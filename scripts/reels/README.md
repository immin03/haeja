# 밸류노트 릴스 자동화

## 구조
- `specs/R*.json` 정기 편성 대본. 새 릴스는 여기에 JSON 하나만 추가하고 푸시하면 GitHub Actions(reels)가 렌더한다.
- `events.py` 3시간마다 지수·환율·금리 급변을 감지해 `events/E*.json` 대본을 만들지만 **자동 게시하지 않는다**(approved=false, 2026-10-20). 관리자에게 소재 감지 알림만 간다.
- `engine.py` 대본 → 1080x1920 영상 (Supertonic 한국어 음성, 합성 배경음악·효과음, 모션, 노래방식 자막).
- `build.py` 바뀐 대본만 렌더 → `social/reels/<id>/reel.mp4, cover.jpg` + `social/reels/queue.json`.
- Supabase `social_reels_fetch/import`(매시 15·18분)가 queue.json을 게시 대기열에 넣고, `social-publish`가 인스타 릴스·쓰레드 영상으로 올린다.

## 대본 쓰는 법 (장면 종류는 engine.py 맨 위 설명 참고)
- 자막(`cap`)만 쓰면 숫자는 자동으로 한글 발음으로 읽는다. 발음이 어색하면 `say`에 한글로 적는다 ("세 배" 권장, "삼 배"는 "삼백"으로 들림).
- 영상 길이는 음성 길이로 정해진다. 장면 4~5개 + cta 면 15~20초, 기승전결을 제대로 담으면 30~50초.
- 금액 예시는 1,000만 원 기준, 결론 장면(statement)은 자극적으로 짧게.
- 고지문은 영상 하단과 게시 본문 끝에 자동으로 붙는다. 캡션에는 쓰지 않는다.

## 댓글 키워드 → DM 정리본 (2026-10-21 운영자 요청, 정보형 릴스 전부)
목표: 릴스 조회 → 댓글(바이럴) → 팔로우 → DM 링크 → 정리본 페이지 이메일(락인) → 카카오 1초 가입. 인스타 앱 '홍보하기' 광고도 같은 게시물이라 그대로 적용된다.
- **정보를 주는 릴스에는 반드시 `dm` 블록을 넣는다.** (넣지 않는 것: 투표·참여형(R09처럼 번호 댓글), 짧은 상식형(R06), 칼럼 소개)
  ```
  "dm": {"keyword": "이자", "title": "매출이 늘었는데 게티이미지는 왜 무너졌을까",
         "points": ["핵심 정리 1 (완결된 문장, 숫자 포함)", "2", "3"],
         "check":  ["내 종목에 적용하는 법 1 (밸류노트에서 실제로 되는 것만)", "2", "3"]}
  ```
- **키워드**: 한 단어, 2~4자, 그 릴스를 대표하는 말(이자·금리·공포·환율·하이닉스·1999). 같은 키워드를 2주 안에 다시 쓰지 않는다.
- **캡션(caption)은 정리본 전체 본문**으로 쓴다(지금처럼 숫자·원인까지 자세히). 인스타에는 build.py가 앞 두 문단 + "💬 댓글에 '키워드'를 남기시면 … DM으로 보내 드립니다"로 줄여 올리고, 나머지는 `/g/<id>` 정리본에 들어간다. 그래서 앞 두 문단은 궁금증을 남기고, 답(원인의 원인·숫자)은 셋째 문단부터 둔다.
- 마지막 장면(cta)은 엔진이 자동으로 "댓글에 '키워드' 남기면 정리본 DM" 버튼과 안내 음성을 붙인다. cta의 l1·l2는 지금처럼 쓴다.
- points·check에 캡션에 없는 숫자를 새로 만들지 않는다. check는 밸류노트에 실제로 있는 기능(기업 상세 이자보상배율, 경제 레이더, 관심 종목 알림, 결정 일지, 메가트렌드, 환율 화면 등)만 쓴다. 밸류노트가 기준을 주지 않는 대상(비트코인 등)은 check를 일반 점검법으로만 쓴다.
- 결과물: `g/<id>.html`(정리본), `g/index.html`(최신순 모음 · 공용 링크), `g/index.json`. 이메일은 Supabase `leads`, 자동 DM 기록은 `ig_dm`, 관리자 소개 페이지 탭 '댓글 DM 정리본'에서 본다.
- 자동 DM은 Supabase 함수 `ig-dm`(app_config `ig_dm_enabled`가 true일 때만 모두에게, 그 전에는 `ig_dm_testers` 아이디만)이 보낸다.

## 품질 관문 (2026-10-20, 모든 릴스가 통과해야 게시)
기준 작품: `specs/N261020c.json` (SK하이닉스, AI가 잘 돼도 위험한 이유).
1. **한 문장으로 말할 수 있는가.** "이 영상은 ○○ 때문에 ○○를 조심해야 한다는 이야기다." 이 문장이 안 나오면 올리지 않는다.
2. **기승전결이 있는가.** 기 = 놀라운 사실·질문(숫자나 유명한 이름) / 승 = 실제로 무슨 일이 있었나(숫자로 확인) / 전 = 반전 또는 원인 하나(예: 매출은 물량이 아니라 가격에서 나왔다, 창신메모리가 빈자리를 채운다) / 결 = 그래서 무엇을 봐야 하나 + 밸류노트가 그 기준을 준다.
3. **숫자에 '그래서'가 붙는가.** 숫자를 나열만 하면 안 된다. "10년 동안 52번"처럼 의미가 따라오지 않는 통계는 쓰지 않는다.
4. **처음 보는 사람이 새로 하나를 배우는가.** 뻔한 교훈("기준을 정하세요", "멀리 보세요")만 남으면 탈락.
5. **밸류노트 연결이 이야기의 답인가.** 앞 내용과 상관없이 붙인 기능 홍보는 탈락.
- 탈락 예: E261020KS11("코스피 장중 -3.3%, 10년간 52번, 기준을 보세요") — 사실 나열 + 뻔한 교훈, 전(轉)이 없음. G02(배당 화면 기능 목록). 틀로 찍은 기업 적정 주가 릴스(A*).
- 전날 밤 품질 점검(20:48)은 고쳐서 기준에 닿지 않는 릴스를 게시 대기열에서 멈춘다(social_posts.paused = true). 아래 "반복 실수 기록"도 함께 점검한다.

## 성과 피드백 (2026-10-20, 릴스를 쓰거나 점검하는 모든 작업이 먼저 읽는다)
릴스 실제 성과(조회수·도달·평균 시청 초·저장·공유)는 3시간마다 `social_posts.ig_insights`에 쌓이고, 밸류노트 비서가 매일 밤 무엇이 통했는지 정리한다.
- 대본을 쓰거나 점검하기 전에 Supabase에서 읽는다: `select data from docs where collection='agent' and id='reels-learn' and owner=publisher_id();` (`works` = 잘 된 패턴, `fails` = 안 된 패턴, `try` = 다음에 시험할 것, 각각 근거 릴스 id·숫자 포함)
- 필요하면 원자료: `select public.agent_snapshot(14) -> 'reels';`
- 품질 관문(위 5가지)이 먼저다. 성과 피드백은 같은 기준을 통과한 후보 가운데 무엇을 고를지, 훅·첫 2초·길이를 어떻게 다듬을지 정하는 데 쓴다. 조회수만 보고 자극적인 소재로 기울지 않는다.
- 게시 후 48시간이 안 된 릴스, 도달 300 미만 릴스는 판단 근거로 쓰지 않는다(표본이 작다).

## 반복 실수 기록 (운영자 피드백이 나올 때마다 여기에 한 줄씩 더한다)
모든 릴스 작업은 대본을 쓰기 전에 이 목록을 읽고, 끝난 뒤 이 목록으로 다시 점검한다. 운영자가 새 문제를 지적하면 그 세션이 바로 한 줄을 더한다.
목표: 보는 사람이 "여기 들어가면 진짜 돈이 되는 걸 알려 주는구나"라고 느끼게 한다. 남들이 다 아는 요약이 아니라, 숫자를 한 번 더 파고든 분석 하나를 준다.
- (10-19) 기능 목록형 릴스 금지. 기능은 이야기의 답으로만 나온다.
- (10-19) "주가에 담긴 기대 vs 실제 성장" 형식은 전달하려는 바가 불분명해 쓰지 않는다. 기업 릴스는 이 회사가 무엇을 하는 회사인지부터.
- (10-20) 주어가 빠진 문장 금지. "메모리 반도체를 만드는 세계 2위 회사입니다" 대신 "SK하이닉스는 …입니다".
- (10-20) 적정 주가에 닿을 가능성이 없는 회사(몇 배 고평가)에 "적정 매수가 알림"을 권하지 않는다.
- (10-20) 숫자 나열 + 뻔한 교훈 금지. 예: "코스피 -3.3%, 10년간 52번, 기준을 보세요" — 그 숫자가 왜 중요한지(그래서)가 없다. 급변 자체는 이야기가 아니다. 왜 빠졌는지, 그게 무엇을 드러내는지가 이야기다.
- (10-20) **결론만 말하지 말고 "왜"를 끝까지 판다.** 게티이미지 첫 릴스는 "AI가 아니라 이자 때문"이라는 결론과 이자보상배율만 보여 주고, 왜 이익이 줄었는지(소송 손실 1억 달러·합병 비용), 왜 이자가 늘었는지(연 9.75% 채권을 14%로 갈아탐), 마지막 한 방(합병 무산·현금 5천만 달러)을 빠뜨렸다. 원인 → 원인의 원인까지 한 단계 더 내려가고, 흔한 통념("AI 때문")을 숫자로 뒤집는다. 고친 판: specs/N261021g.json.
- (10-21 점검) **연구·자료는 핵심 발견까지 읽고 쓴다.** F05 첫 판은 바버·오딘 연구에서 '덜 번 숫자'만 가져와 '뉴스를 보면 실수한다'는 통념으로 채웠지만, 연구의 진짜 발견은 '비용 빼기 전 수익은 시장 이상이었고, 차이는 사고판 횟수에서 났다'였다. 자료가 말하지 않는 것(1990년대 자료로 '앱을 자주 열수록')을 훅에 쓰지 않는다. 밸류노트가 기준을 주지 않는 대상(비트코인 등)에 '기준은 밸류노트에서'를 답으로 붙이지 않는다(X261021 멈춤).
- (10-20) 기준 작품은 specs/N261020c.json(SK하이닉스): 지금 상황 → 남들이 모르는 분석 하나(가격 vs 물량, 창신메모리) → 리스크 → 워렌 버핏 기준 적정 주가 → 틀릴 수 있는 이유 → 밸류노트.

## 썸네일 (cover.jpg, 2026-10-18 개편)
- 영상 첫 장면을 그대로 잡지 않고 따로 그린다. 틀(남색·금색·로고·하단 훅 문장·시리즈 표시)은 같고 가운데 그림이 시리즈마다 다르다.
  - 기능 소개(F) → 앱 화면, 기업(A) → 기대·실제 막대, 금리(M) → 선 차트, 쉬운 가이드(G) → 목록, 교육(R) → 큰 숫자
  - 프로필 격자는 세로 4:5로 가운데를 잘라 보여 주므로 요소는 모두 y 285~1635 안에 둔다.
- 대본에 `"cover": "bars"`(장면 종류) 또는 `"cover": 2`(장면 번호)를 쓰면 직접 고를 수 있고, `"tag": "..."`로 시리즈 표시를 바꿀 수 있다.
- `engine.COVER_V`를 올리면 `build.py`가 아직 올라가지 않은 릴스의 썸네일만 다시 그린다(영상은 그대로).

## 앱 화면 장면 (screen)
- `capture.js` 가 체험 계정으로 앱 화면 전체를 캡처하고(`screens/<이름>.png`), 블록별 글자·위치를 `screens/<이름>.json` 에 저장한다.
  화면: portfolio, companies, company(기업 상세), briefing, radar, trends, alerts, journal, level
- 대본: `{"type":"screen","shot":"company","stops":[{"find":"현재가","label":"적정 가격까지 계산"}]}`
  `find` 글자가 들어 있는 블록을 찾아 스크롤하고 금색 박스로 강조한다. 맞지 않으면 `"box":[x0,y0,x1,y1]`(이미지 픽셀)로 직접 준다.
- 앱 디자인이 바뀌면 `node scripts/reels/capture.js` 로 다시 캡처한다.

## 대본 규칙 (모든 릴스·카드뉴스 공통, 반드시 지킨다)
처음 보는 사람이 한 번 듣고 이해해야 한다. 짧게 줄이는 것보다 친절하게 풀어 쓰는 것이 우선이다.

1. **기준은 문장으로 풀어 쓴다.** "좋은 회사인가 40점"이 아니라 "돈을 잘 버는지, 빚이 적은지, 이익이 꾸준한지를 보고 좋은 회사인지를 40점 만점으로 평가합니다."
2. **숫자에는 분모와 뜻을 붙인다.** "60점 이상 → 실패 15%"가 아니라 "60점 이상이었던 27개 종목 중 실패한 종목은 4개, 약 15%였습니다."
3. **낯선 말은 처음 나올 때 바로 뜻을 말한다.** 적정 주가(회사가 앞으로 벌 돈으로 계산한 1주당 가치), 실패(산 뒤 손해를 봤거나 본전에 그친 투자), 버크셔 해서웨이(버핏이 이끄는 회사), PER(주가가 1년 이익의 몇 배인지), ROE(주주 돈 100원으로 1년에 번 이익). 뜻을 말할 시간이 없으면 그 말을 쓰지 않고 쉬운 말로 바꾼다.
4. **자막과 음성은 같은 문장이다.** 한 줄(lines 하나) = 완결된 한 문장. 문장을 두 줄에 걸쳐 끊지 않는다. say를 따로 쓸 때도 자막과 같은 뜻·같은 순서로 쓴다(숫자 읽는 법만 다를 수 있음).
5. **자막 한 줄은 18자 안팎**, 한 화면 두 줄까지. 길면 문장을 나눈다. 화면 글자에 "→"를 쓰지 않는다(글꼴에서 ">"처럼 보인다). "A원이 B원으로"처럼 말로 쓴다.
6. **TTS가 뭉개는 말은 피한다**: "매깁니다"(→ 채점합니다). 브랜드명은 korean.py가 "밸유 노트"로 읽게 바꾼다. 새로 뭉개지는 말을 찾으면 korean.py WORDS에 추가.
6-1. **모든 문장에 주어를 밝힌다 (2026-10-20 운영자 지시).** "메모리 반도체를 만드는 세계 2위 회사입니다"처럼 주어 없이 시작하지 않고 "SK하이닉스는 …"처럼 누가·무엇이를 넣는다. 특히 장면이 바뀐 뒤 첫 문장, 회사 소개, 숫자를 말하는 문장("○○의 적정 주가는 …"), 앱 기능 문장("밸류노트는 …")은 반드시 주어를 쓴다. 앞 문장과 주어가 같아도 장면이 바뀌면 다시 쓴다.
6-2. **인물 이름은 전체 이름으로 (2026-10-20 운영자 지시).** 버핏은 항상 "워렌 버핏", 멍거는 "찰리 멍거"로 쓴다(자막·음성·제목·썸네일·캡션·해시태그 모두). "버핏 기준"이 아니라 "워렌 버핏 기준". 해시태그는 #워렌버핏 #찰리멍거.
7. **말투는 ~합니다체**, 반말·명사형 끝맺음("~쌈", "~함")은 쓰지 않는다.
8. **길이에 얽매이지 않는다 (2026-10-20 운영자 변경, 이전 20~40초).** 보통 30~50초, 꼭 필요하면 60초까지 된다. 길이를 맞추려고 "왜"를 설명하는 문장을 잘라 내지 않는다. 다만 이야기에 보탬이 안 되는 문장은 길이와 상관없이 뺀다. 60초를 넘으면 렌더가 멈춘다. 속도는 1.1(기본).

9. **화면이 멈춰 있는 순간을 두지 않는다.** 엔진이 자동으로 넣는 움직임: 장면 내내 천천히 다가가는 카메라, 새 문장마다 살짝 튀는 박자, 떠오르는 입자, 자막 줄이 차례로 올라오기. 대본에서는 한 장면에 문장 3개 이상을 몰지 말고, 3초 넘게 같은 그림이 이어지면 장면을 나눈다.

10. **용어는 하나만 쓴다 (앱·카드·릴스·캡션 공통).** 밸류노트 점수(점수는 이것 하나) · 재무 점수 · 가격 점수 · 정성 평가 · 트렌드 · 적정 주가(적정가/적정 가격/내재가치 금지) · 적정 매수가(적정 주가의 70%) · 저평가/고평가(앱 화면용. 릴스·캡션에서는 규칙 13에 따라 쓰지 않는다) · 안전마진은 그레이엄 원칙 설명에만.

11. **첫 2초 후킹 (가장 중요).** 화면 첫 문장만 보고 멈추게 만든다. 소리 없이 보는 사람이 많으니 큰 글자(top·숫자)만으로도 뜻이 통해야 한다. 인사·"오늘은" 같은 도입부 금지, 첫 문장에 숫자나 아는 이름을 넣는다. 첫 줄에서 궁금하게 만들고 둘째 줄에서 숫자로 답한다. 쓰는 공식:
    - 질문(내 일처럼): "삼성전자, 지금 사도 될까요?" / "이 주식, 왜 샀는지 기억나세요?"
    - 손실·위기감(결과 먼저): "배당 8% 주고 산 주식, 1년 뒤 33% 잃었습니다"
    - 통념 뒤집기: "주식 가치 계산은 늘 틀립니다" / "반토막 나면 50%가 아니라 100% 올라야 본전"
    - 비교·반전: "같은 회사 주식을 샀는데 10년 뒤 2.7배 차이"
    - 숫자 약속: "회사 이름만 넣으면 몇 초 만에 채점합니다"
    - 권위·검증: "버핏이 산 종목 62개를 채점해 봤습니다"
   강한 말을 쓰되 사실만: 지어낸 숫자·과장("무조건", "100% 오른다") 금지, 예시는 예시라고 알 수 있게.

12. **금융 상식은 이슈와 엮어 쉽게 푼다 (2026-10-19 운영자 변경).** PER·PBR·이자보상배율·채권 가격과 금리 같은 상식도, 실제 사건이나 회사 하나에 붙여 '그래서 이게 무슨 뜻인지'를 한 문장으로 풀면 쓴다. 밸류노트 기능만 소개하는 영상보다 금융을 하나 배워 가는 영상을 우선한다. 개념 자체를 강의하듯 설명하는 것은 여전히 하지 않는다. (옛 규칙) **어려우면 올리지 않는다.** 금융을 처음 보는 사람이 영상만 한 번 보고 이해하지 못할 내용(PER 배수 변화, 백테스트 같은 개념 설명. 역DCF는 이름을 쓰지 않고 "지금 주가가 맞으려면 이익이 매년 N% 늘어야 합니다"로만 말한다)은 만들지 않는다. 그 대신 밸류노트 기능 소개(점수, 저평가·고평가, 관심 종목 알림, 배당, 환율, 금리, 경제 레이더, 메가트렌드, 칼럼, 브리핑, 결정 일지, 등급, 직접 분석 등)와 아주 쉬운 상식(반토막 나면 100% 올라야 본전, 복리) 위주로 만든다. 판단 기준: "중학생이 한 번 보고 따라 말할 수 있는가".

13. **기업 릴스는 결론부터 말한다 (2026-10-19 운영자 변경, 이전 규칙 대체).** "버핏의 기준으로 계산한 ○○의 적정 주가는 얼마"라고 결론을 먼저 내리고, 자세한 분석은 밸류노트에서 확인하게 한다. 기본 형식은 `company_cards.mjs`의 `value`:
    - 기: 버핏 기준 적정 주가 + 지금 주가는 적정 주가의 몇 배(또는 몇 % 쌈) → 두 가격 비교 + "시장은 왜 이보다 비싸게(싸게) 사고 있을까요?"
    - 승: 무슨 회사인지 (프로필 `what`)
    - 전: 그 회사에 실제로 쓰인 계산 원리 하나 (경기순환: 평균 이익 · 꾸준한 우량주: 성장의 75% · 금융사: 순자산이 버는 돈 · 일반: 10년 현금 · 평균 이익). 최근 이익이 평균보다 훨씬 크면 "최근 이익이 계속된다면 적정 주가는 ○○"라는 반전을 넣는다.
    - 결: 이 계산이 틀릴 수 있는 이유(호황이 길면, 시장이 믿는 성장이 맞다면, 싼 데는 이유가 있을 수 있음) + "자세한 계산은 밸류노트 ○○ 분석에서".
    - 적정 주가는 밸류노트의 의견이 아니라 버핏·그레이엄 방식의 계산 결과라고 말하고, 이 방식이 늘 맞지는 않는다는 점을 함께 쓴다. 숫자는 그날 데이터에서만.
    - 조건(적정 주가 있음·데이터 신뢰도 정상·회사 소개 있음)이 안 맞으면 5년 주가(price) → 무엇으로 돈을 벌까(intro) 순으로 대신한다.
    - 순위 릴스(15:30)는 사실 순위: 돈 잘 버는 회사 TOP 10(평균 ROE) / 배당 꾸준한 회사 TOP 10. 결론은 "좋은 회사도 가격은 따로 봐야 합니다".
14. **비교·상식 릴스를 중간중간 넣는다.** "10년 전 1억이면 지금 얼마"(비트코인·ETF·삼성전자·금·코스피, 원화 기준, 최대 하락 함께), "3배 레버리지의 함정"처럼 몇 년 뒤 결과를 직관적으로 보여 주는 형식. 결론은 수익 자랑이 아니라 '버틸 수 있었는가·기준이 있는가'로 밸류노트 콘셉트에 맞춘다.

15. **품질 체크리스트 (모든 릴스, 올리기 전에 하나라도 걸리면 고친다).** (2026-10-19 운영자 지시: 편수보다 질)
    - **0~3초 후킹:** 소리 없이 첫 화면만 봐도 질문이 읽히는가. hook의 `top`은 큰 흰 글씨 두 줄짜리 질문(줄당 12~14자, 줄바꿈 `\n`)이고, 숫자는 그 질문의 답이어야 한다. "3가지", "5개 시장", "1분"처럼 질문 없이 숫자만 크면 실패.
    - **직관성:** 처음 보는 사람이 한 번 보고 한 문장으로 따라 말할 수 있는가. 메시지는 하나, 낯선 말은 쓰지 않거나 바로 풀어 쓴다.
    - **끝까지 보게 하는 흐름:** 질문 → 답 → 반전이나 비교 → 나에게 주는 의미 순서. 3~4초마다 화면이 바뀌고, 답을 첫 장면에서 다 보여 주지 않는다.
    - **문구 규칙:** 자막 = 음성, 한 줄 18자 안팎, 화살표 금지, 금지어(무료/유료, 지어낸 숫자·과장) 없음, 캡션 본문에 고지문 없음(게시 때 * 한 줄 자동). 적정 주가는 규칙 13의 결론형으로 쓴다.
    - **밸류노트에 들어가고 싶은가:** 마지막 장(cta)은 일반 문구("더 현명한 투자를 시작하세요") 대신 이 영상과 이어지는 구체적인 이유를 준다. 예: "지금 가격이 적당한지는 밸류노트에서", "적정 매수가에 오면 밸류노트가 알려 드립니다", "회사 이름만 넣으면 바로 점수가 나옵니다". 캡션 마지막 문단도 같은 이유로 끝낸다.
    - **음성 검수:** 모든 문장을 로컬에서 들어 보고(tts.speak → verify.hear → verify.score) 0.9 미만이면 더 쉬운 말로 바꾼다. 자주 뭉개지는 말: 몫, 빚, 위험 신호는, 메모리, 영문 약어, 1위는.
16. **기승전결 스토리 (2026-10-19 운영자 지시).** 모든 릴스는 정보 나열이 아니라 이야기여야 한다.
   - 기: 의외의 사실·질문 (예: 삼성전자보다 더 오른 보험회사가 있다?)
   - 승: 무슨 회사·무슨 일인지 + 숫자·차트로 확인
   - 전: '왜 그런가'를 알려 주는 금융 원리 하나 (예: 보험사는 보험료를 먼저 받아 굴린다 = 플로트, 버핏이 보험사를 사랑한 이유). 보는 사람이 하나 배워 가야 한다.
   - 결: 한 문장 교훈 + 그 교훈을 밸류노트에서 확인하는 이유.
   - 하지 않는 것: '배당 여력이 있다', '무리하지 않는 배당' 같은 놀랄 거리 없는 정보 나열(배당 형식은 2026-10-19 중단). 30초 안에 끝나야 한다(목표 25초).

## 음성 검수 (자동)
- `tts.py`는 문장을 절 단위로 나눠 읽는다(길게 한 번에 읽으면 음절을 빼먹는다).
- `verify.py`가 합성된 음성을 한국어 음성 인식으로 다시 받아 적어 대본과 맞춰 본다. 90% 미만이면 설정을 바꿔 다시 합성하고, 끝까지 85% 미만이면 그 릴스는 렌더를 멈추고 대기열에서 뺀다. 결과는 `social/reels/<id>/voice_check.json`.
- 자막(cap)과 음성(say)이 크게 다르면 ⚠ 경고가 나온다.
- 로컬에서 끄려면 `REELS_VERIFY=0`.

17. **실제 영상 배경·효과음 (2026-10-19).** 첫 장면(후킹) 뒤에는 주제에 맞는 무료 실사 영상을 어둡게 깐다(글자가 먼저 읽히게, 끝 0.45초 동안 기본 배경으로 넘어감).
   - 클립: `assets/broll/<주제>_<번호>.mp4` (Mixkit 무료 라이선스, 상업적 이용 가능·출처 표기 불필요). 받기: `assets/manifest.json` 에 번호를 넣고 푸시하면 reels-assets 작업이 받아 세로로 잘라 커밋한다.
   - 주제 고르기: 제목·해시태그·캡션 앞부분 낱말로 자동(engine.py BROLL_RULES: 보험→도로, 반도체→칩, AI→데이터센터, 위기·폭락→폭풍, 금리·환율→도시 야경, 앱·알림→휴대폰, 복리·장기→시계 …). 대본에 "broll": "<주제>" 로 지정하거나 "none" 으로 끈다.
   - 효과음: `assets/sfx/*.wav` (장면 전환 휙, 후킹 숫자 쿵, 금액이면 동전 소리, 목록 톡, 앱 화면 클릭, 마지막 알림 벨). 파일이 없으면 직접 합성한 소리로 돌아간다.
   - 금지: 실제 인물·회사 로고가 주인공처럼 보이는 클립, 다른 회사 제품을 그 회사인 것처럼 보이게 하는 클립.

## 점수·적정 주가는 시점을 맞춘다 (2026-10-21)
지금 계산한 점수·적정 주가로 과거 매수 결정이나 과거 주가를 평가하지 않는다. 과거 매수 이야기에는 매수 당시 점수(index.html `VALIDATION.purchases`)를 "매수 당시 ○○점 → 지금 ○○점"으로 함께 쓰고, 과거 주가 그래프에 지금 적정 주가를 겹칠 때는 "지금 계산한 적정 주가"라고 밝히며 과거 저평가·고평가로 결론 내리지 않는다. 알파벳 예시는 "버크셔는 이 방식으로 지금 고평가인 알파벳을 올해도 더 샀다"처럼 시점을 붙인다. 자세한 규칙은 scripts/blog/README.md.
